\section{Experimental Setup}
\label{sec:setup}
\subsection{Evaluation protocol in the original study}
Gao et al.~\cite{gao-etal-2021-simcse} used separate data for learning
sentence representations, selecting a checkpoint, and evaluating semantic
textual similarity (STS), as summarized in Table~\ref{tab:paper-data}.

\begin{table}[htbp]
\caption{Data used by Gao et al.~\cite{gao-etal-2021-simcse}}
\label{tab:paper-data}
\centering\footnotesize
\begin{tabular}{@{}p{0.33\columnwidth}p{0.60\columnwidth}@{}}
\hline
Data & Role in the study \\
\hline
English Wikipedia & Train unsupervised SimCSE on one million randomly sampled sentences. \\
SNLI and MNLI & Train supervised SimCSE using 314k entailment pairs as positives and contradictions as hard negatives. \\
STS-B development set & Select batch size and learning rate. Evaluate every 250 training steps to select the best checkpoint. \\
STS12, STS13, STS14, STS15, STS16, STS-B, SICK-R & Evaluate the selected encoder on seven English similarity tasks. \\
\hline
\end{tabular}
\end{table}

For each sentence pair, the authors encoded the two sentences separately
and computed the cosine similarity of their embedding vectors. Across
pairs, Spearman's $\rho$ measured agreement between the ranks of these
cosines and the ranks of human similarity judgments. This choice matches
the goal of STS: a pair judged more similar by annotators should receive a
higher cosine score, even though the two scores use different scales.
Even the supervised
encoder was evaluated directly. Its training labels came from natural
language inference, and no regressor was fitted on STS training data.

For STS12--STS16, the aggregation protocol called \emph{all} pooled the
topic subsets within each year before computing one correlation for that
year. The Avg.\ column then gave equal weight to each of the seven tasks.
The published STS-B split contains 1,500 development pairs and 1,379
test pairs.\footnote{Cer et al., Table~11,
\url{https://aclanthology.org/S17-2001/}.} SentEval lists approximately
4,900 test pairs for SICK-R.\footnote{\url{https://github.com/facebookresearch/SentEval#evaluation-tasks}}

The authors report using NVIDIA 3090 GPUs with CUDA~11 for the published
experiments.\footnote{SimCSE training documentation at commit
\texttt{235f89e}, \url{https://github.com/princeton-nlp/SimCSE/tree/235f89e#training}.}

% Recorded environments: experiments/reproduction/results/R1/env.txt,
% experiments/reproduction/results/R2/env.txt and experiments/reproduction/results/R3/env.txt.
For R1--R3 we evaluated the released checkpoints on CPU using the original
script at commit \texttt{235f89e}. The environment used Python 3.11.9,
PyTorch 2.5.1+cpu, Transformers 4.46.3 and NumPy 1.23.5. Each checkpoint
was evaluated on the same seven English STS tasks with the pooling shown in
Table~\ref{tab:sts-reproduction}.
% R4 environment: experiments/reproduction/results/R4-2026-11-24/env.txt.
The independent loss experiment used Python 3.14.0 and PyTorch 2.9.1+cpu.

\subsection{ViRHE4QA Retrieval Setup}
\label{sec:d1-setup}
We used the public ViRHE4QA subset~\cite{do2024r2gqaretrieverreadergeneratorquestionanswering}
distributed with ViRE~\cite{nguyen-quan-2026-works}.
% Counts and split provenance: outputs/d1-test/inputs/split.json.
After removing 17 exact duplicate questions from 1,000 rows, we retained
983 questions, each linked to one reference passage. We split the questions
by reference passage with seed 42. D1-dev contains 224 questions linked to
59 distinct passages, and D1-test contains 759 questions linked to 238
distinct passages. The two splits have disjoint sets of reference passages
and share the same searchable corpus of 297 passages. We assigned all four
questions in the group containing query 9542 to D1-dev because that query
appears as an example in Section~\ref{sec:intro}.

We used the supervised SimCSE-VN checkpoint released by VoVanPhuc
(\texttt{VoVanPhuc/sup-SimCSE-}\allowbreak\texttt{VietNamese-phobert-base})
(Section~\ref{sec:method-pipeline}). Both questions and passage text underwent
Unicode NFC normalisation, tone-mark normalisation and pyvi word segmentation.
We split passages into chunks of at most 256 tokens, including special
tokens. The encoder returned \texttt{pooler\_output}, which we L2-normalised
before computing exact cosine similarities with NumPy. Under MaxP, each
passage received the highest cosine score among its chunks, and we retained
the 20 highest-ranked distinct passages for each question.

% Selection grid and coverage target: experiments/external_dataset/results/D1-dev-tuning/summary.json.
We selected the BM25 weight on D1-dev by maximising MRR@10 over
weights from 0.0 to 1.0 in increments of 0.1. For the selected
Hybrid ranking, we chose the largest observed cosine threshold retaining
at least 80\% of its queries as confident. Both settings are fixed for
the subsequent test evaluations.
